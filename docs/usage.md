# 零零谷九汇城店微信小程序

面向密室逃脱门店店长与员工的任务、积分和订单进度管理应用。项目使用 uni-app Vue 3，可同时构建 H5 预览和微信小程序。

## 本地预览

```bash
npm install
npm run dev:h5
```

## 构建微信小程序

```bash
npm run build:mp-weixin
```

只预览小程序页面时，可导入：

```text
dist/build/mp-weixin
```

需要使用微信页面订阅提醒时，请在微信开发者工具中导入项目根目录。根目录的 `project.config.json` 已同时配置小程序构建目录和 `cloudfunctions` 目录。

## 逐页视觉回归

`design-previews` 是批准的 390 × 844 设计基线，`visual-regression` 保存同尺寸运行截图。更新界面后执行：

```bash
npm run visual:check
```

11 个页面的平均像素差必须低于 3/255，避免后续业务开发破坏已确认的设计稿。

## 当前功能

- 微信端顶部按系统状态栏及胶囊位置动态预留空间，消息、头像和各详情页操作按钮放在胶囊下方；滚动区同步下移。页面显示及尺寸变化时重新计算，H5 保持原布局。
- 员工端仅显示未完成订单，不提供「已完成」筛选。选择「不要视频」或完成所需剪辑后，订单立即隐藏并关闭员工详情；店长仍可查看历史。仅改变显示，不删除订单、收款、积分和操作记录；店长回退流程后，待处理订单会重新出现在员工端。
- 订单列表使用 12 个两字进度标签：创建、开始、开复、收钱、带场、入场、进行、结束、收复、拍照、视频、完毕；选择不要视频后直接完毕，不要求剪辑。
- 收钱节点支持填写微信、支付宝、现金、线上金额，可混合收款，至少一项大于 0，精确到分。确认后继续带场节点，只登记金额，不发起实际支付。
- 店长概览显示当日微信、支付宝、现金及三项合计；线上金额只记录，不计入该日合计。按设备本地收款日期统计，跨日自动显示新一天。
- 店长概览保留最近 7 个自然日的微信、支付宝、现金及合计记录。取消或删除订单会把关联收款标记为已冲正，并从当日及 7 日汇总中扣除。
- 点击右上角头像可在员工端和店长端之间切换。
- 员工端覆盖积分任务、积分明细、排行、抢单、创建与修改订单、订单节点推进、拍照/视频分支和消息通知。
- 店长端覆盖经营概览、打扫任务审核、临时任务发布、订单修正、取消和删除入口。
- 店长可进入员工管理，新增、停用、恢复或删除员工账号；删除后该员工积分立即从团队总积分中移除，待审核任务同步取消。
- 店长可查看每名员工近一个月的积分明细，并撤销单笔已到账正积分；员工端明细同样只保留近一个月。
- 店长可在「我的 → 积分任务设置」新增或修改任务名称、分类、奖励积分和审核规则。已到账和待审核记录保留提交时的积分。
- 店长可在「我的 → 主题管理」新增、修改和删除主题，初始录入开学悸等 12 个实际主题。主题配置用于新订单与新维修；历史订单不会被自动改名。
- 顶部「维修」入口供员工和店长使用，按主题填写必填问题备注，登记为待维修；任一在职员工或店长可标记已完成，并保留登记人、修理人和完整日期时间。
- 流程节点、消息通知、积分明细、抢单大厅和打扫审核统一显示“月日 时分”；临时任务同时显示发布时间和抢单时间。
- 员工问候和店长概览标题随本地时段变化，门店名称统一为“零零谷 · 九汇城店”；店长概览最多直接显示 6 条订单现场。
- 店长把订单退回“收钱”节点后，可修改原微信、支付宝、现金或线上金额，修改不会新增重复收款。
- 订单开始按钮显示具体主题名称，完成后节点显示「《主题名》· 已开始」，并保留开始时的名称。
- 临时任务可限制指定在职员工领取，未被选择的员工端不会显示该任务。
- 业务数据已使用版本化本地存储，刷新、退出后仍然保留。
- 普通积分任务立即到账；打扫任务进入审核，通过后才到账。
- 今日积分和任务点击次数会在本地日期跨日时自动归零；审核通过会同步更新对应员工的积分与完成次数。
- 临时任务采用“抢到即结束”规则，不需要员工再次提交完成。
- 选择“要视频”会建立关联剪辑任务，但不会发送通知；剪辑完成后订单结束。
- 店长专属操作在界面显示和方法入口两层校验，员工不能取消、删除、修正订单或审核任务。

## 主题、积分和维修使用说明

- 员工和店长：顶部「维修 → 需要修理」，选择主题并填写问题备注后登记；修好后点击该记录的「已完成」。已完成记录在对应筛选中查看。
- 店长：切换店长端后，「我的 → 积分任务设置」修改任务名称与积分。积分支持 0 到 1000000 的整数，改分不会重新计算旧记录。原有打扫任务的名称可在此自行替换，不会擅自给新增主题分配打扫积分。
- 店长：「我的 → 主题管理」维护名称。删除为软删除，新建订单和维修不再提供该选项，已有订单与待维修记录仍可继续处理。
- 已有订单保留当时填写的主题名称；修改主题配置不会批量修改订单。员工可以编辑订单内容，已开始节点仍显示开始当时的主题名称。
- 初始主题：开学悸、港诡实录、旅店惊魂、医怨、夜嫁、雨夜屠夫、忌屋、捉妖、我帮太爷打鬼砸、通灵鬼校、玩惧屋、诡画2。

运行配置和维修规则回归：

```bash
npm run test:store-config
```

## 上线前的后端接入

当前版本可以在单台设备完整运行和保存数据。正式给多名员工同时使用前，需要把 `services/app-state.js` 的本地存储替换为微信云开发或自有后端，至少包含：

- 微信登录、员工与店长角色绑定；
- 订单、积分、审核、通知的多端实时同步；
- 主题配置、积分规则、维修记录的云端共享，以及服务端配置权限和维修完成幂等校验；
- 收款记录的云端保存、服务端防重复登记以及门店时区统一，不能把本地演示的收款数据用于正式财务对账；
- 抢单接口的服务端原子锁，确保多人同时点击时只有一人成功；
- 服务端时间和不可篡改的操作日志；
- 店长删除采用软删除并保留审计记录。

## 微信页面订阅提醒

1. 在微信公众平台为小程序选择订阅消息模板，模板字段使用 `thing1`、`thing2`、`time3`。
2. 复制 `.env.example` 为 `.env.local`，把模板 ID 写入 `VITE_WECHAT_SUBSCRIBE_TEMPLATE_IDS`；多个模板用英文逗号分隔。
3. 在微信云开发中新建 `notification_subscribers` 集合，并部署 `cloudfunctions/sendStoreNotification`（云端安装依赖）。
4. 重新执行 `npm run build:mp-weixin`，在微信开发者工具中导入项目根目录。用户进入“消息通知”后点击“开启提醒”完成授权。

站内消息始终保留；微信订阅消息依赖真实小程序账号的模板 ID、用户授权和已部署的云环境，H5 预览不会伪造发送成功。

## 收款记录说明

收款台账独立于订单保存。回退到收钱节点时可修改原记录，不会新增重复收款；取消或删除订单会把关联记录标记为已冲正，并从汇总中剔除。冲正是本系统的账面撤销标记，不会自动发起微信或支付宝退款。

历史订单原先只有“已收钱”状态、没有金额，不会自动补造收款金额，也不会纳入日合计。新的收款、积分、员工与提醒配置一同保存在 v5 本地数据中。

```bash
npm run test:payments
npm run test:redlines
```
